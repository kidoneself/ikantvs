# 需求：自营录入 / 同行录入

后台内容中心两个独立菜单。都是「粘贴标题 + 网盘链接 → 进搜索池」，**不绑影视库、不追更、不进每日更新**。差别只在链接归谁、用户怎么拿到。

| | 同行录入 | 自营录入 |
|---|---|---|
| 菜单 | 内容中心 → 同行录入 | 内容中心 → 自营录入 |
| 入库 `source` | `pool` | `self` |
| 前台展示 | 普通池资源 | 站长精选 |
| 用户点「获取链接」 | 用**上游源链**走临时转存（会清理） | 直接给**我方永久分享链**（已转到站长号） |
| 是否动站长网盘 | 否 | 是，转入片库目录 |

`media_id = 0`（未绑剧哨兵）。去重键：`pan_type + share_id`（只在未绑剧池内）。

---

## 1. 共同：粘贴解析

两种录入共用同一套解析，一次最多约 8 万字 / 200 条。

```
「混沌少年时 (2025)」
链接：https://pan.quark.cn/s/d1392249bbde

❤️10部合家欢国风动画电影
https://pan.quark.cn/s/3b0b5b32a6f7
下载地址: https://pan.baidu.com/s/xxxx?pwd=abcd
提取码：ab12
```

规则：

- 第一条有效文字当标题；标题后的碎语忽略，直到下一条 URL。
- 连续多条 URL 共用当前标题。
- 行首「链接 / 下载地址 / 地址 / 分享 / 网盘」可有可无。
- 百度 `?pwd=`、下一行「提取码 / 密码 / 访问码」。
- 识别夸克、百度、阿里、迅雷、UC、磁力、ed2k 等已有盘种；认不出的 URL 跳过。
- 标题命中敏感词 → 该条跳过，不整批失败。

后台就是一个大文本框 + 提交 + 结果表（标题、盘种、链接、状态、原因）。不做 Excel 导入（那是另一条需求）。

也可走结构化 body：`{ "items": [{ "title", "url", "password?" }] }`，给脚本用。

---

## 2. 同行录入

**只入库，不转存。** 搜索能搜到，用户获取链接时用源链做临时转存。

### 2.1 行为

1. 解析文本。
2. 按 `pan + shareId` 查找未绑剧池：没有则新增 `source=pool`，有则更新标题/源链（**不得覆盖**已是 `source=self` 的行）。
3. 写入搜索索引（标题用 `note`，没有影视片名）。
4. 返回新增 / 更新 / 跳过条数及明细。

### 2.2 后台

- 路径：`/content/pool`（对外文案「同行录入」）。
- 按钮：「入池」。提交后立刻出结果，不用轮询。

### 2.3 接口

| 方法 | 路径 | 鉴权 |
|---|---|---|
| POST | `/api/admin/pool/ingest` | 运营 JWT，**或** 开放 Token |

Body：`{ "text": "..." }` 或 `{ "items": [...] }`。

Token 与自营共用系统配置 `pool.self.token`（空 = 脚本接口关闭）。Header：`X-Api-Token` 或 `Authorization: Bearer`。限流：每 IP 约 30 次/分钟。

脚本调这个接口时不要走前台 Origin 校验。

## 3. 自营录入

**先转到站长号，再进搜索。** 完成后 `source=self`，前台当站长精选；用户拿的是我方链，不再用上游链做临时转存。

### 3.1 行为

1. 解析文本（同上）。
2. 写入未绑剧池：`source=self`，源 URL 可先空，`note=标题`。
3. 用该盘**当前片库号**做一次永久转存，落地目录 **「自营片库」**（不要进「临时转存」，也不要和每日更新的「追更资源」混用）。
4. **不**开启巡检、**不**进每日更新看板。
5. 我方链就绪后再更新 `media_link.url` 并灌搜索索引；链还没出来时不要把空 URL 的 self 文档搜出来。
6. 已有我方链则跳过，不重转。

进度：`transferring` / `done` / `failed`；`done` 时带 `shareUrl`。

### 3.2 后台

- 路径：`/content/pool-self`（对外文案「自营录入」）。
- 按钮：「转存并入池」。提交后结果表轮询进度（约 3 秒），展示源链 / 我方链 / 失败原因。

该盘未指定片库号、且该盘也不止一个号时：明确报错，引导去转存页指定。**不要**默默占用每日更新的追更号。

### 3.3 接口

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| POST | `/api/admin/pool/self` | 仅运营 JWT | 后台页 |
| GET | `/api/admin/pool/self?id=` | 仅运营 JWT | 查一条进度 |
| POST | `/api/open/pool/self` | 开放 Token | 脚本 / 助手 |
| GET | `/api/open/pool/self?id=` | 开放 Token | 脚本查进度 |

开放 Token 未配置 → 401。限流同同行录入。开放路径跳过前台 Origin 校验。

脚本同样不要自己去转网盘，只 POST 站点，由站点片库号执行。

## 4. 转存账号：每盘两个指针（不要互斥标签）

账号表仍是「一行 = 一次登录」。**不要**用互斥的 `transfer / monitor / pool` 三种标签，也不要按网盘名写死「迅雷例外」。

每盘只配置两个当前号（下拉，可以选同一个账号）：

| 指针 | 用途 | 落地目录 |
|---|---|---|
| 追更号 | 每日更新巡检 | `追更资源` |
| 片库号 | 自营录入 | `自营片库` |

规则：

- 两个指针可以指向**同一个账号**（迅雷只有一个号时，两个下拉都选它）。这不是加号两次，库里仍一行。
- 有备用号时，片库号和追更号选不同账号，避免合集把追更号空间占满。
- 片库号满了：只改「片库号」指向下一个；旧号上的我方链不动。
- 没被这两个指针点到的号，进用户**临时转存**池，目录 `临时转存`，到期清理。
- 某盘只有一个可用号、指针未配：回退用这唯一的号。某盘有多个号却没配片库号：自营录入失败并提示去配置。

清理只删 `临时转存`。`追更资源` / `自营片库` 永久保留。自营任务不要复用「启用中的监控巡检」；一次性转存即可。

---

## 5. 搜索与前台

- 未绑剧池用标题（`note`）检索，不查影视库片名。
- `source=self` 标站长精选。
- 同行：获取链接 → 临时转存 → 给用户一份会过期的我方链。
- 自营：获取链接 → 已有永久我方链则直接给；没有则视为未就绪。
- 空 URL 的 self 行不要进索引。

---

## 6. 明确不做

- 不创建 / 不绑定 `media` 影视条目。
- 不进每日更新、不开追更巡检。
- 不在录入页选账号、不每次粘贴挑号。
- 不做 Excel 批量（同行后台那种导入是另一需求）。
- 不做转存后改名、附加宣传文件（网盘配置里的那套是另一需求）。
- 开放 Token 当普通用户口令用；未配置则脚本接口不可用。

---

## 7. 开源落地

- 代码放 `content` 域（解析、入库、开放接口）+ `transfer` 域（片库号、永久转存、目录）。后台菜单在 `admin`。
- 默认值用占位，不写生产域名。Token 只走系统配置 `pool.self.token`。
- 接口统一 `Result<T>`；业务错误 `BizException`。
- 提交信息前缀 `pub:`。

### 后台菜单

| 文案 | 路由 | 最低角色 |
|---|---|---|
| 同行录入 | `/content/pool` | contributor |
| 自营录入 | `/content/pool-self` | contributor |

转存页增加每盘「追更号 / 片库号」两个下拉，去掉账号行上互斥的分工下拉（若还在的话删掉）。
