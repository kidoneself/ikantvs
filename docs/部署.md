# 部署指南

开源版 **一份 compose 即可**：业务镜像已含后端 + 前台 + 后台 + 建表 SQL，**不用** clone 源码、**不用**本机 build。

| 入口 | 地址 |
|------|------|
| 前台 | `http://服务器IP:3080` |
| 后台 | `http://服务器IP:3081`（默认 `admin` / `admin123`，**务必改密**） |

镜像：`ghcr.io/kidoneself/ikantvs`（`main` 推送后由 GitHub Actions 构建）。Package 需为 **Public**，否则 `pull` 会 401。

---

## 方式一：宝塔（推荐）

1. 宝塔安装 **Docker**
2. 打开 [`deploy/docker-compose.yml`](https://github.com/kidoneself/ikantvs/blob/main/deploy/docker-compose.yml)，全选复制  
3. 宝塔 → Docker → **编排** → 添加 → 粘贴  
4. 同目录建 `.env`（可从 [`.env.example`](https://github.com/kidoneself/ikantvs/blob/main/deploy/.env.example) 复制），至少改：

```env
MYSQL_ROOT_PASSWORD=换成强密码
DB_PASSWORD=换成强密码
JWT_SECRET=至少32位随机字符串
CORS_ALLOWED_ORIGINS=http://你的公网IP:3080
```

5. 启动编排，等镜像 pull 完成（首次较慢）  
6. 云厂商安全组 / 宝塔防火墙放行 **3080**、**3081**

打开前台与后台验证即可。首次启动会跑一轮夸克热榜灌库（约数分钟），片库会逐渐变多。

---

## 方式二：命令行

```bash
mkdir -p /opt/ikantvs && cd /opt/ikantvs

# 只需两份文件
curl -fsSL -o docker-compose.yml \
  https://raw.githubusercontent.com/kidoneself/ikantvs/main/deploy/docker-compose.yml
curl -fsSL -o .env.example \
  https://raw.githubusercontent.com/kidoneself/ikantvs/main/deploy/.env.example
cp .env.example .env
# 编辑 .env：密码、JWT、CORS_ALLOWED_ORIGINS=http://公网IP:3080

docker compose pull
docker compose up -d
docker compose ps
docker compose logs -f app   # 看启动与夸克灌库
```

若已 clone 仓库，也可在 `deploy/` 下：

```bash
cd deploy
./deploy.sh init   # 生成 .env
# 编辑 .env
./deploy.sh up
./deploy.sh status
./deploy.sh logs app
```

## 启动后建议

1. 后台登录 → **系统 → 后台账号** 改掉 `admin` 密码  
2. **系统 → 系统设置**：网盘页签开关、公告等按需改；可选在「资源采集」启用 Gying 并填写账号  
3. 等夸克灌库结束（日志含 `[quark-ranking] 同步完成`），前台即有片可搜  
4. 点片名搜链依赖 `pansou` 容器（及可选 Gying）；内存紧见下文

## 环境变量（常用）

| 变量 | 说明 | 默认 |
|------|------|------|
| `MYSQL_ROOT_PASSWORD` / `DB_PASSWORD` | 数据库密码 | 示例弱密码，必改 |
| `JWT_SECRET` | 登录签名密钥 | 示例值，必改 |
| `CORS_ALLOWED_ORIGINS` | 前台来源，逗号分隔 | `http://127.0.0.1:3080` |
| `QUARK_RANKING_ENABLED` | 夸克热榜灌库 | `true` |
| `QUARK_RANKING_INTERVAL_MS` | 翻页请求间隔（防风控） | `500` |
| `INGEST_PANSOU_ENABLED` | 是否调 pansou 搜链（首次种子，之后以后台为准） | `true` |
| `ENABLE_PANSOU` | 是否起 pansou 容器（与上配合） | `true` |
| `INGEST_GYING_ENABLED` / `INGEST_GYING_ACCOUNTS` | Gying 开关与账号（首次种子；日常请在后台「资源采集」改） | 默认关 / 空 |
| `JYINSHI_CLOUD_*` | 云端片库（**未实现**，开了也不会同步） | 默认关 |
| `R2_ENABLED` | Cloudflare R2 远程海报 | `false` |
| `APP_IMAGE` | 业务镜像覆盖 | `ghcr.io/kidoneself/ikantvs:latest` |

完整示例见 [`deploy/.env.example`](../deploy/.env.example)。

## 内存紧 / 不要 pansou

机器约 **2G** 或只想先看片库时：

1. 编辑 compose，**删掉整个 `pansou:` 服务**  
2. `.env` 设：

```env
INGEST_PANSOU_ENABLED=false
ENABLE_PANSOU=false
```

3. 重启编排。前台仍可浏览片库与每日更新；点搜链会不可用。

---

## 绑定域名

1. DNS A 记录指向服务器  
2. 宝塔加站点 → 申请 SSL → 反代 `http://127.0.0.1:3080`（后台可另反代 `3081` 或子路径）  
3. `.env`：`CORS_ALLOWED_ORIGINS=https://你的域名`  
4. `docker compose up -d` 重启 `app`

## 常见问题

| 现象 | 处理 |
|------|------|
| `pull` 401 | GHCR Package 设为 Public，或本机 `docker login ghcr.io` |
| 前台空白 / CORS | 核对 `CORS_ALLOWED_ORIGINS` 与浏览器地址一致（含 `http/https`、端口） |
| 后台进不去 | 确认 3081 已放行；默认账号 `admin` / `admin123` |
| 片库很少 | 看 `app` 日志是否在跑 `[quark-ranking]`；首次需等数分钟 |
| 搜不到链 | 确认 `ikantvs-pansou` 在跑，且 `INGEST_PANSOU_ENABLED=true` |
| 与现有 Docker 冲突 | 本编排容器名均为 `ikantvs-*`，一般可并存 |

查看日志：

```bash
docker compose logs -f app
docker compose logs -f pansou
```

## 升级

```bash
cd /opt/ikantvs   # 或你的编排目录
docker compose pull
docker compose up -d
```

数据在 Docker volume（`ikantvs_mysql_data`）里，升级不丢库。重大版本若有说明再按迁移文档操作。
