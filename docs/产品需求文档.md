## 0. 一句话定义

> 一个**网盘影视资源信息流平台**：用户浏览/搜索影视信息流 → 进详情看「这部片有哪些网盘分享链接 + 提取码」→ 用户自己复制链接去转存。
> 平台**只做信息聚合与展示，不接管用户网盘、不做一键转存**。
> 商业模式：会员订阅制（结构预留，先全员免费）。

与老设计方案最大的差异：**砍掉转存域**。平台不持有用户网盘账号、不替用户转存，只呈现分享链接。

---

## 1. 产品定位与核心体验

- **信息流优先**：首页/搜索呈现的是「内容信息」（海报、简介、类型、年份、更新状态），不是冷冰冰的"找到 N 条资源"。参考 seedhub.cc 的清爽信息流 + 左上角大海报、其余小卡的版式。
- **只展示网盘链接**：详情页列出该资源在各网盘（夸克/百度/阿里/迅雷…）的分享链接 + 提取码，用户**自行复制**去转存。详情页动作只有「复制链接」。
- **登录是增值不是门槛**：不登录也能浏览、搜索、看详情、看链接（付费墙关闭时）。登录后解锁**收藏、追剧（更新提醒）**等个人化功能。

## 3. 商业化模型（⚙️ 需拍板）

砍掉转存后，原来「按转存次数收费」的付费点没了，需要重新选一个付费点。候选：

| 方案 | 免费用户 | 会员 | 备注 |
|---|---|---|---|
| **A. 链接付费墙** | 看得到信息，**链接/提取码需会员** | 看全部链接 | 变现最直接，但削弱"游客可用"体验 |
| **B. 内容分层** | 普通资源全看 | **精品/最新/4K 等专区**会员可见 | 体验温和，需要给内容打标 |
| **C. 体验增值** | 有广告、搜索有频控 | 去广告、无频控、追剧提醒更快 | 最温和，变现弱 |
| **D. 纯免费 + 后续再定** | 全开放 | —— | 先不收费，结构预留 |

**推荐默认：D（先全免费跑量）+ 结构上预留 A/B 的开关**。等有流量再决定付费点。
> 无论选哪个，技术上都靠 `isMember()` 单一出口 + 付费墙开关控制，不影响现在开发。

### 3.1 收款与会员开通（已定：站外发卡 + 站内卡密）

```
聚发货等发卡平台          爱看 jyinshi-next
─────────────────        ─────────────────
上架商品（月/季/年卡）      后台批量生成 redeem_code
微信/支付宝收款            （复制卡密导入平台库存）
自动把卡密发给买家    →    用户回站「/activate」核销
                           member_expire_at 顺延/叠加

邮箱查订单（购买时在平台填写的邮箱）：
  ① 聚发货 API 查订单 → 取卡密 → 核销（jyinshi.billing.platform.enabled）
  ② webhook 售出回调 → 写入 redeem_code.buyer_email → 邮箱匹配未用卡密
  ③ 该邮箱曾激活过 → 直接登录
```

- **Webhook**：`POST /api/billing/webhook/delivery-order`，Header `X-Webhook-Secret`，body `{ code, buyerEmail }`

- **套餐**：月 / 季 / 年单一等级，`plan` 表描述天数；展示价格在 `sys_config`（`plan.price.*`）与发卡平台商品页维护，两边手动对齐即可。
- **购买链接**：`billing.shop_url` 配置聚发货店铺地址，前台「去购买」跳转。
- **明确不做**：主站接入微信/支付宝、订单支付回调、`order` 表。
- **可选后续**：发卡平台 webhook 自动发码（仍非直连支付，只是库存同步自动化）。

### 5.1 内容数据模型（信息与链接分离）

核心思想：**内容身份锚定在元数据(media)，网盘链接(media_link)单独一张表挂上去**。
元数据优先来自 TMDB/豆瓣（喂 id 自动抓）；链接按来源分「录入 / 搜索 / 抓取」，详情页分层展示。

```sql
-- 信息表：一部片/一个条目一行（元数据单独存）
media(
  id,
  tmdb_id, douban_id, bangumi_id,         -- 外部 id，喂任一个即可自动抓
  type,                                    -- movie/tv/anime/variety
  title, original_title, year,
  poster, rating, overview,                -- 海报/评分/简介（TMDB 直连抓取）
  genres, country, status,                 -- 类型标签/地区/连载完结
  hot,                                     -- 热度（榜单/排序）
  tier,                                    -- 普通/精品/专区（付费分层预留）⚙️
  meta_source,                             -- tmdb/douban/manual/none(仅标题)
  created_at, updated_at
)
-- 允许"只有标题、暂无元数据"的临时条目（新片 TMDB 还没收录时）

-- 网盘链接表：挂在某个 media 下，一对多
media_link(
  id, media_id,
  pan_type,            -- quark/baidu/aliyun/xunlei/...
  url, pwd, note,      -- 链接 / 提取码 / 备注
  source,              -- ⭐ manual录入 / pansou搜索 / crawl抓取
  status,              -- pending待审 / approved已发布 / rejected驳回
  contributor_id,      -- 谁提交的（录入员）
  match_score,         -- 自动匹配置信度（搜索来源用）
  invalid, report_count,  -- 失效标记 / 用户举报数
  created_at, updated_at
)

-- 录入/贡献审计（激励与防滥用）
contribution_log(id, user_id, media_id, link_id, action, result, created_at)

-- 收藏 / 追剧
user_favorite(id, user_id, media_id, created_at)            -- 唯一键(user_id, media_id)
user_follow(id, user_id, media_id, last_seen_ep, created_at)

-- 榜单
ranking(id, name, type, sort) / ranking_item(id, ranking_id, media_id, rank)
```

### 5.2 详情页链接展示规则

- `source=manual`（人工录入/确认的优质链接）→ **默认展开**，台面主角。
- `source=pansou`（聚合搜索来的）→ **折叠「更多来源(N)」**，用户点开再看。
- `invalid=true` 或举报多的链接 → 置灰/降序/隐藏。

> 这样「搜索对不上」不再是问题：搜索链接降级为可折叠的次要来源，不强求精确匹配。

> 用户/会员表（user 等）已建。`plan` / `redeem_code` 已建（V014）。**无 order 表**。
> ⚠️ `tier`（内容分层）和「链接付费墙」开关是为将来变现预留，先全开放。

## 6.5 内容采集（开放录入平台）—— 本项目命脉

内容靠**三个进货口**，但都汇到「候选 → 审核/校准 → 发布」一条管道，不直接上线：

```
①录入员/用户录入 ┐
②搜索聚合(PanSou) ├─► 候选(media_link.status=pending) ─► 审核 ─► 发布(approved) ─► 信息流
③自动抓取(可选)   ┘            ▲
                  TMDB 直连：喂 tmdb_id/豆瓣id 抓海报/分类/评分/简介 → media 表
```

### 来源 B：元数据/海报（单条采集，给链接即可）✅ 已实现
- **单条采集，不做跨源兜底**：给一个 **TMDB 链接/id** 或 **豆瓣链接/id**，就采那一个源。
  - TMDB：海外机直连 `api.themoviedb.org`，需配 `TMDB_API_KEY`（v3）。
  - 豆瓣：走 frodo 移动端 API + HMAC-SHA1 签名（同 MoviePilot），用豆瓣 App 公开 apikey/secret，**无需自备 key**。已验证可拿到标题/海报/评分/简介/题材/国家/演员/导演/集数。
- 接口：`POST /api/admin/media/import`，body 传 `{"url": "豆瓣或TMDB详情页链接"}` 或 `{"tmdbId":..,"type":".."}` / `{"doubanId":".."}`。
- 都没有：`POST /api/admin/media/manual` 建「仅标题」条目（`meta_source=none`），等有 id 再 `refresh` 补抓。

### 来源 A：网盘链接（自部署独立 PanSou）⚙️ 已定：新部署一个专用 PanSou
- 给 PanSou 一个标题/关键词 → 返回各网盘分享链接 → 落 `media_link`，`source=pansou`，`status=pending`。
- **搜索不强求精确**：搜来的链接在详情页是**折叠的次要来源**；自动用 TMDB 匹配打 `match_score`，高分可自动挂、低分进人工审核。

### 来源 C：人工录入（开放平台）
- 录入员选/填 TMDB 条目（自动带元数据）→ 贴网盘链接 → `source=manual`。
- 录入即候选，审核通过才发布；可信录入员可后审/免审。`contribution_log` 记账，将来做激励（换会员时长/贡献榜）。

### 审核/校准
- 候选队列：每条显示 链接+note+系统猜的 TMDB 匹配(带海报)，审核员一键「确认/改匹配/驳回」。
- 失效治理：用户举报 → `report_count`↑ / `invalid` → 详情页降级或隐藏。

> ⚠️ 影响：开放录入/审核**本身就是后台功能**，需随 content 域做一个**最小录入/审核台**；完整运营后台仍可往后放。
