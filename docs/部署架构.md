# jyinshi-next 部署架构总纲

> 最后更新：2026-07-29。现网拓扑「广州唯一后端 + 香港出海网关」；另有**单机单域名**交付方式。
> 以后要改部署，先看这份，别口头重讲。

## 0. 海外单机单域名（开源默认 / 给别人一套）

不拆广州/香港。多数人只有**一台海外 VPS**（香港/新加坡/美西等均可），跑全栈、**一个域名**（前台 + `/api` 同源；后台 `IP:8080`）。建议 2 核 4G+。

```bash
cd deploy
./deploy-single.sh init          # 生成 .env.single
# 编辑 SITE_DOMAIN / ACME_EMAIL / MYSQL_* / JWT_SECRET
# 可选：JYINSHI_CLOUD_* 对接上游；ENABLE_PANSOU=false 省内存
./deploy-single.sh up            # 本机执行
# 或：DEPLOY_SERVER=root@IP SSHPASS=... ./deploy-single.sh all
```

空库初始化走 `deploy/init/`（最终态 schema + 演示种子），不是重放 `migrations/` 历史。

文件：`docker-compose.single.yml`、`Caddyfile.single`、`.env.single.example`、`deploy-single.sh`。

## 3. 复用的 MySQL / Redis（都在广州、都是老项目的容器）

| 组件 | 容器 | jyinshi-next 用 | 老项目用 | 密码 |
|---|---|---|---|---|
| MySQL 8.0 | `jyinshi-mysql` | 库 `jyinshi_next` | 库 `jyinshi_db` | root: `root123456` / 业务: `jyinshi`/`jyinshi123` |
| Redis 7 | `jyinshi-redis` | **db 1** | db 0 | `redis123456` |

隔离方式：**独立库 + 独立 Redis db index**，两项目共用实例互不干扰。

广州 backend 连接参数（写在 `deploy/.env.guangzhou`，由发布脚本生成）：
```
DB_URL=jdbc:mysql://jyinshi-mysql:3306/jyinshi_next?...&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
DB_USERNAME=jyinshi   DB_PASSWORD=jyinshi123
REDIS_HOST=jyinshi-redis   REDIS_PORT=6379   REDIS_PASSWORD=redis123456   REDIS_DATABASE=1
```
所有容器接入外部网络 `jyinshi_jyinshi-network`（老项目建的），故能用容器名互连。

## 4. 发版方式

### 广州（后端/前台/后台）
```bash
cd deploy
export SSHPASS='Lzq951201@'          # 广州 root 密码
./deploy-guangzhou.sh all            # 全量：同步+env+构建+Caddy+sys_config+健康检查
./deploy-guangzhou.sh stack          # 只重建 backend/web/admin
./deploy-guangzhou.sh caddy          # 只同步老 Caddyfile 并重载 jyinshi-frontend
./deploy-guangzhou.sh config         # 只刷 sys_config（TMDB 反代 + 迅雷回调）
./deploy-guangzhou.sh health
```
- compose 文件：`deploy/docker-compose.guangzhou.yml`（**不含** mysql/redis/caddy，接 external 网络）。
- 大陆前台 API base：`VITE_API_BASE=https://ik.naspt.vip/api`（同源，全程走广州）。

### 香港（静态前台 + 网关）
```bash
cd deploy
export SSHPASS='toYp3DgLv0'          # 香港 root 密码
./deploy-hk-gateway.sh all           # 同步 + 切换网关栈 + 健康检查
./deploy-hk-gateway.sh cutover       # 只停旧栈起网关栈
```
- compose 文件：`deploy/docker-compose.hk-gateway.yml`（pansou + web + caddy）。
- Caddy：`deploy/Caddyfile.hk-gateway`。
- 海外前台 API base：`VITE_API_BASE=https://api.naspt.vip/api`。
- **禁止**再用 `./deploy-prod.sh`（已停用，会误在香港起 backend/mysql）。香港日常只动 `./deploy-hk-gateway.sh`。

> ⚠️ **香港 web 构建的坑（已踩过）**：compose 会自动读 `deploy/.env`，里面 `VITE_API_BASE=https://api.ikantvs.com/api` 会**覆盖**默认值，导致 ikantvs.com 前端调 `api.ikantvs.com`（被 301 跳转 → 预检 OPTIONS 不跟随 301 → 跨域失败）。
> 重建香港 web 必须显式覆盖：
> ```bash
> VITE_API_BASE=https://api.naspt.vip/api docker compose -f docker-compose.hk-gateway.yml up -d --build web
> ```

广州 backend `CORS_ALLOWED_ORIGINS` 必须含所有前台域名：
```
https://ik.naspt.vip,https://admin.naspt.vip,https://ikantvs.com,https://www.ikantvs.com
```

## 7. 关键约束（防止再乱）

1. **只能有一个后端操网盘账号**。网盘凭据（迅雷 refresh_token 会滚动）唯一真身，两个 backend 同时跑转存/追更/探活会互相搞挂。当前唯一后端在广州；香港 backend 已下线；广州老的独立 `transfer-worker` 容器已停删。
2. **80/443 归老项目 Caddy（`jyinshi-frontend`）**。jyinshi-next 广州栈**不起自己的 Caddy**，vhost 追加进老项目 `jyinshi/frontend/Caddyfile`，改完 `./deploy-guangzhou.sh caddy` 重建生效。
3. 老项目 Caddyfile 里 jyinshi-next 的段用容器名 `jyinshi-next-backend/web/admin`（和老的 `jyinshi-backend`/`jyinshi-frontend` 不撞）。

## 8. 数据迁移（已完成一次，供参考重做）

香港现导 → 广州导入：
```bash
# 香港 dump
ssh root@149.88.68.90 "docker exec jyinshi-mysql mysqldump -uroot -proot123 \
  --single-transaction --routines --triggers --set-gtid-purged=OFF jyinshi_next | gzip > /tmp/d.sql.gz"
# 拉回本地再推广州（或直接机器间传）
# 广州导入（会重建库）
ssh root@175.178.182.111 "docker exec jyinshi-mysql mysql -uroot -proot123456 -e \
  \"DROP DATABASE IF EXISTS jyinshi_next; CREATE DATABASE jyinshi_next CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci; \
    GRANT ALL PRIVILEGES ON jyinshi_next.* TO 'jyinshi'@'%'; FLUSH PRIVILEGES;\" && \
  gunzip < /tmp/d.sql.gz | docker exec -i jyinshi-mysql mysql -uroot -proot123456 jyinshi_next"
```
广州 MySQL 时区已确认 `+08:00`，审计列不会差 8 小时。

## 10. 常见问题速查

| 现象 | 原因 / 处理 |
|---|---|
| ikantvs.com 跨域 | 香港 web 打包成了 `api.ikantvs.com`；按 §4 用 shell 变量重建指向 `api.naspt.vip`；然后强刷浏览器 |
| naspt.vip「没数据」 | 多为浏览器缓存旧页；强刷（Cmd+Shift+R）。后端数据实际正常 |
| 某域名 502 | 对应 upstream 容器没起；`docker ps` 看容器；相关 compose `up -d` |
| 广州发版 rsync `Permission denied` | 偶发；`export SSHPASS='Lzq951201@'` 后重试，或分步 `sync`/`stack` |
| SSH 密码 | 广州 `Lzq951201@`；香港 `toYp3DgLv0`（也在 `deploy/.env` 的 SSHPASS） |
