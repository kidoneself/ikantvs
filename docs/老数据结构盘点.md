## 2. ⚠️ 关键结论（已更正）

新产品定位是「**展示网盘分享链接**的信息流」，而 **`search_cache`（1.8 万条）正是为此量身定做的数据**：
每条 = 一个关键词/内容条目，自带 TMDB 元数据（分类/年份/评分/海报/简介）+ `results_json` 内**按网盘类型分组的分享链接**（夸克/百度/迅雷，含提取码、备注、来源、失效标记）。

- **主内容源 = `search_cache`**：1.8 万条带链接 + 1 万条带海报，NSFW 已清零，直接可做信息流主体。
- `daily_update`（2465）：做「每日更新/追剧」板块。
- `media_metadata`（3145）：当 `search_cache` 海报/简介缺失时的增强兜底。
- `auto_resource`（9.7 万 m3u8）：在线播放数据，**新产品不直接用**（无网盘链）。

> 修正了上一版「可用链接只有 ~2500 条」的判断——加上 `search_cache` 后，可用内容约 **1.8 万条**。
> 阶段 2 直接以 `search_cache` 为主源迁移/接入即可。

## 3. 表结构详情（老实体字段）

### search_cache —— ⭐ 主内容源（关键词 = 内容条目，含多网盘链接 + 元数据）
```
id, keyword, keyword_hash,
results_json,                           -- ⭐ 核心：所有网盘结果（见下方结构）
total_count, quark_count, baidu_count, xunlei_count,
-- TMDB 分类信息 --
category(movie/tv/anime/variety/other), genre(逗号分隔), country, year, rating,
poster_url(本地 /poster/xxx.jpg), tmdb_id, overview, is_nsfw,
-- 热度 --
search_count, daily_search_count, last_search_date, heat_level(0普通/1热门/2超热),
last_refresh_time, refresh_status, first_search_time, last_search_time,
created_at, updated_at
```

`results_json` 结构（实测样本）：
```json
{
  "total": 501,
  "merged_by_type": {
    "quark":  [ { "url": "https://pan.quark.cn/s/xxxx",
                  "password": "F2Cg",          // 提取码，可能为 "" 或 null
                  "note": "逐玉[4K全40集]...",   // 标题/描述/简介
                  "datetime": "昨天",            // 时间（有的是ISO，有的是中文"今天/昨天"）
                  "source": "plugin:gying",     // 来源插件，可能为 null
                  "invalid": false },           // 是否已失效
                ... ],
    "baidu":  [ ... ],
    "xunlei": [ ... ]
  }
}
```
> 注意：`password`/`source`/`datetime` 字段质量参差（有 null、空串、中文相对时间），迁移时需清洗。

### daily_update —— 每日更新/追剧（含网盘链接）
```
id, title, type(movie/tv/anime/variety),
baidu_link, quark_link, xunlei_link,   -- 网盘分享链接（含提取码）
sort, latest_episode,                   -- 最新集数/日期
created_at, updated_at
```

### resource —— 通用资源（links 为 JSON）
```
id, title, description, cover,
links(JSON: {pan_type: url}),           -- 网盘链接映射
tags(JSON), extra(JSON), source,
status(0下架/1上架), click_count,
link_type(0自有/1外部需转存),
created_at, updated_at
```

### media_metadata —— 元数据镜像（增强展示，无网盘链）
```
id(复合: tmdb:123/douban:xxx/bangumi:xxx),
tmdb_id, douban_id, bangumi_id,
title, original_title, year, rating, poster,
type(movie/tv/anime/unknown), genre, overview,
release_date, last_air_date, country, status,
episode_count, season_count, runtime,
actors_json, directors_json, type_name,
created_at, updated_at
```

### auto_resource —— 自动采集目录（97k，m3u8 在线播放，无网盘链）
```
source, vod_id, media_key,              -- 复合身份
name, sub, en, type_id, type_name, vod_class,
area, lang, year, actor, director, blurb,
pic, pic_local, remarks, douban_score,
episode_count(自算), is_end, remarks_type,
src_time, created_at, updated_at
```

### auto_resource_episode —— 分集直链（208万，ffm3u8，新产品不需要）
```
id, source, vod_id, episode_name, episode_index,
play_url(m3u8 直链), created_at, updated_at
```

### ranking / ranking_item —— 榜单
```
ranking: id, name, type, sort, status, created_at, updated_at
ranking_item: id, ranking_id, title, keyword, cover_image, description, sort, ...
```

## 4. 与新 content 域表的映射建议（将来迁移时）

| 新表 | 主要来源 | 说明 |
|---|---|---|
| `resource` | **`search_cache`**（主）+ `media_metadata`（增强）+ `daily_update` | 一条 search_cache → 一个 resource；元数据(category/year/rating/poster/overview)直接搬 |
| `resource_link` | `search_cache.results_json.merged_by_type` 拆行 + `daily_update` 三链 + `resource.links` | 一资源多链接，按 pan_type 拆；带 pwd/note/invalid |
| `ranking`/`ranking_item` | 老 `ranking`/`ranking_item` | 基本可平移 |
| 敏感词 | `sensitive_word` | ops 域复用 |

> 迁移要点：search_cache 的 `results_json` 要解析 `merged_by_type` → 每个 pan_type 下每条 → 一行 `resource_link`；
> 清洗：丢弃 `invalid=true`、去重 url、规整 `datetime`、`password` 统一空值。海报 `poster_url` 是本地路径，需迁图或改走图片代理。

> 迁移做法（将来）：一次性脚本 老库 SELECT → 清洗（去无效链接/敏感词）→ 新库 INSERT，不连老代码。
